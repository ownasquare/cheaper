## What was wrong

`sync-prices.js` printed this on every `npm test`, and had done since the route-target gate
was added:

```
ROUTE TARGET TIER MISMATCH: mistral.sonnet -> 'mistral-small-4' is catalogued as tier 'haiku'
ROUTE TARGET TIER MISMATCH: mistral.opus -> 'mistral-medium-3.5' is catalogued as tier 'sonnet'
route targets: 18 entries resolve; 2 known tier mismatch(es) ratcheted
```

Both were real defects, and both are the measurement-honesty failure this product exists to
avoid — a call answered below the tier it is *reported* as:

| slot | held | its catalogued tier | effect |
|---|---|---|---|
| `mistral.sonnet` | `mistral-small-4` | **haiku** | a mid-tier request answered one tier down, reported as mid |
| `mistral.opus` | `mistral-medium-3.5` | **sonnet** | an auto-escalated *hard* request answered by a MID-capability model, reported as top tier |

The second is the same shape as the defect already recorded in `pricing.js` against the
gateway's OpenAI front end, whose top tier was `o3` (a `sonnet`-tier model).

## Why it had not been fixed

Both ledger entries named the same blocker: a `mid <= top` **price** assertion in
`cli/test/peek.test.js`. Correcting the slots to `mistral-medium-3.5` ($9.00 per 1M-in/1M-out)
and `mistral-large-3` ($2.00) makes `mid <= top` false, so the gate was ratcheted instead.

**The assertion was the cause, not a constraint.** It inferred capability order from price,
which `models.js:59-64` forbids in as many words:

> `tier` is a CAPABILITY class … It is NEVER a price proxy. … capability rank and price rank
> genuinely disagree: `claude-fable-5` is a top model at $60/Mtok blended while
> `claude-opus-5` is a top model at $30, and **Mistral's flagship costs less than its mid
> model**.

and which `peek.test.js`'s own test `capability tier and price rank are allowed to disagree`
asserts outright for this exact pair. The suite therefore held two contradictory requirements,
and the route table was the side that gave way — for the one family where the catalog says
price and capability invert.

## The change

1. **`cli/src/peek/pricing.js`** — `ROUTE_TARGET.mistral` mid → `mistral-medium-3.5`
   (tier sonnet), top → `mistral-large-3` (tier opus). `mistral-large-3` is both the correct
   opus-tier target **and** cheaper than the model it replaces ($0.5/$1.5 vs $1.5/$7.5), so
   this raises capability and lowers cost.
2. **`cli/test/peek.test.js`** — the `mid <= top` assertion is **removed** and replaced by:
   - `cheap <= top` (kept price shape: the cheap slot may never be the most expensive), and
   - a new test, `every route-target slot names a model OF THAT SLOT'S TIER`, which reads each
     target's declared tier out of the catalog and permits exactly one exception — a family
     publishing no model of a tier falls back **DOWN**, never UP.

   A long comment sits where the old assertion was, explaining why re-adding any `mid <= top`
   ordering is a regression.
3. **`cli/scripts/sync-prices.js`** — `KNOWN_TIER_MISMATCHES` is now `{}`. The machinery is
   untouched: an unlisted mismatch still fails, and a listed one that stops reproducing still
   fails, so the ledger can only shrink to empty and stay there. The former entries are
   recorded in the comment above it.
4. **`cli/assets/gateway/app/model_prices.json`** — regenerated by `node scripts/sync-prices.js`.
   The diff is exactly four lines (`route_targets.mistral` and its bucket-keyed twin); no other
   key or price moved.

## Two pinned counts moved, and the drop is the point

`policy_parity.test.js`'s same-tier-substitution census went **73 / 63 / $1851.20 → 63 / 53 /
$1803.50**.

That was verified independently rather than read off the code under test: the census was
re-run with the OLD Mistral map injected through `opts.router` (the same hook the live gateway
uses), and it reproduced 73 / 63 / $1851.20 exactly — so the method is sound and the new
numbers are trustworthy.

Exactly ten `(model, content)` pairs left the set and **none entered**:

- `mistral-medium-3.5` /sonnet /opus — the sonnet slot now names this model itself, so there
  is no substitution left to price.
- `magistral-medium`, `mixtral-8x22b`, `devstral-2`, `codestral` /sonnet — each is cheaper than
  the $9.00 sonnet target, so `router.py`'s **dollar ceiling** now walks them down; they are
  honest tier DOWNGRADES (`routedTier` haiku), not same-tier routes.
- the same four /opus — the classifier calls these hard, so the **quality floor** stops the
  ceiling from walking below the escalated tier and they PASS THROUGH.

The $47.70 that left reconciles to the cent against `mistral-small-4`'s $0.75 basket:

```
(9.00-0.75)*2 + (7.00-0.75)*2 + (8.00-0.75)*2 + (2.40-0.75)*2 + (1.20-0.75)*2
= 16.50 + 12.50 + 14.50 + 3.30 + 0.90 = 47.70   ( = 1851.20 - 1803.50 )
```

It was never a same-tier saving. It was a tier downgrade wearing a same-tier label, and the
census is smaller because it is now honest.

## Blast radius

`mistral` is **not** in `ROUTABLE_FAMILIES` (`['anthropic', 'openai']`), so no gateway route
changes and the peek headline is untouched — Mistral's counterfactual is reported in the
separate unroutable bucket. Nothing in the arithmetic assumed price monotonicity across tiers:
`pricing.js:334-346` already documents the signed, unclamped delta and gives a worked example
of a "cheaper" tier target costing more (`gemini-3.5-flash` vs `gemini-2.5-pro` on
input-heavy calls).
