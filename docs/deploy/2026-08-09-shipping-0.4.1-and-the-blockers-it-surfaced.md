# Shipping 0.4.1: four release blockers that only a real release could find

**Date:** 2026-08-09/10 · **Follows:** [2026-08-09-preflight-gate-and-the-dead-release-matrix.md](2026-08-09-preflight-gate-and-the-dead-release-matrix.md)
**Shipped:** desktop **0.4.1** — GitHub Release with 12 assets, all 9 stable R2 keys updated, website live.
**Not shipped:** the CLI on npm. Still **0.4.0** (published 2026-08-08 from an earlier tree). See *Open* below.

---

## Why the version is 0.4.1 and not 0.4.0

`cheaper@0.4.0` was published to npm on **2026-08-08 18:18 UTC**, from the Aug-8 tree. It
does not contain the Mistral route-target correction, the catalog price verification, or
peek's reconciliation counters. npm versions are immutable, so today's CLI could not reuse
that number, and `cheaper-desktop` followed to keep the lockstep the deploy enforces.

The same staleness had reached the installers. `node_modules/cheaper` is a **symlink** to
`../../cheaper-app/cli`, so an installer bundles whatever the CLI directory held at build
time. The dmgs in `dist/` were built 2026-08-08 10:42 and bundled the Aug-8 CLI while being
named 0.4.0 — a stale build under a correct version number, which is precisely the case the
filename VERSION GUARD cannot see. Rebuilt; the new dmgs differ from the previously-live
objects by md5, which is the proof the staleness was real and not theoretical.

## The four blockers, in the order they surfaced

Each was invisible until the layer above it was fixed. None could have been found by
reading the file.

### 1. `npm install` could never have worked in CI

`package.json` declares `"cheaper": "file:../cheaper-app/cli"` — a path **outside** the
repository. `actions/checkout` brings only `cheaper-desktop`, so the path does not exist on
any runner.

This arrived in `740b6e5`, the same commit that added the 3-OS matrix, four hours after the
last green run. Combined with the invalid `if:` expression fixed earlier, the two masked
each other perfectly: every run died at parse time, before `npm install` could report the
real problem. **The matrix had never once run in its current form.**

Fixed by checking out both repos as siblings, with `ownasquare/cheaper` pinned to the tag
being released so the bundled CLI is the CLI that shipped. `upload-artifact`'s `path:` had
to move to `cheaper-desktop/dist/*` as well — it is workspace-relative and is *not* covered
by `defaults.run.working-directory`.

### 2. macOS: an absent secret is an empty string

`CSC_LINK: ${{ secrets.CSC_LINK }}` with no such secret sets `CSC_LINK=""`.
electron-builder resolves that as a relative path, which becomes the working directory:

```
⨯ /Users/runner/work/cheaper-desktop/cheaper-desktop/cheaper-desktop not a file
```

A directory nobody wrote, three levels of repo name deep, with no mention of signing. The
Windows step four lines above has carried a comment about this exact defect since it was
written; the macOS side had it too and had never been exercised.

### 3. Linux arm64: electron-builder only ships an x86 fpm

It downloads `fpm-1.9.3-2.3.1-linux-x86` and then cannot execute it on arm64
(`ruby: cannot execute binary file: Exec format error`). The message names ruby, so it
reads as a corrupt download rather than "this packager has no arm64 build". The lane now
installs a native fpm plus `rpmbuild` and sets `USE_SYSTEM_FPM`.

### 4. I reintroduced blocker 2 while fixing blocker 3

`USE_SYSTEM_FPM: ${{ matrix.os == 'ubuntu-24.04-arm' && 'true' || '' }}` yields `''` on the
x86_64 lane, and app-builder tests that variable for **presence, not truthiness** — so the
empty string still meant "use the system fpm", on the one lane with no system fpm. It broke
`ubuntu-latest`, which had built successfully in the previous run.

The remedy is the same in both places and now applied consistently: `unset` if empty. **An
absent value has to be an absent variable; setting it to `""` is setting it.**

## The arm64 filenames were derived, then confirmed

The arch token is not uniform across packagers, and guessing one spelling for all three is
how a key ends up quietly stale. Derived from `builder-util/out/arch.js::toLinuxArchString`
(which returns `aarch64` for pacman/rpm/flatpak and `arm64` otherwise), then confirmed
against the real build log:

| target | filename | R2 key |
|---|---|---|
| deb | `Cheaper-0.4.1-arm64.deb` | `cheaper-linux-arm64.deb` |
| rpm | `Cheaper-0.4.1-aarch64.rpm` | `cheaper-linux-arm64.rpm` |
| AppImage | `Cheaper-0.4.1-arm64.AppImage` | `cheaper-linux-arm64.AppImage` |

## What is live

All nine keys verified after a CDN purge — the macOS two by md5/etag against the local
signed builds, the rest by upload timestamp.

| key | source | state |
|---|---|---|
| `cheaper-macos-arm64.dmg` · `cheaper-macos-x64.dmg` | local signed build | **0.4.1**, etag matches local |
| `cheaper-windows-x64.exe` | CI | **0.4.1** (was **2026-08-07**) |
| `cheaper-linux-amd64.deb` · `-x86_64.rpm` · `-x86_64.AppImage` | CI | **0.4.1** (were **0.1.0**) |
| `cheaper-linux-arm64.deb` · `-arm64.rpm` · `-arm64.AppImage` | CI | **0.4.1**, new keys |

The three x86_64 Linux keys had been serving **0.1.0** — content-length matched the deleted
0.1.0 artifacts exactly. That skew was live for days.

**dl.cheaper.app caches for 4 hours** (`cf-cache-status: HIT`, `max-age=14400`). An upload
is not a publish until the cache is purged; both macOS objects and the Windows exe read as
stale for ~50 minutes after a successful upload. Purged via the zone API.

`cheaper.app` redeployed with arm64 download links on `/post-download` and `/thanks`,
x86_64 entries relabelled by architecture. Playwright 154/154.

> Note for the next reader: `/post-download.html` returns **307** to `/post-download`.
> A `curl` without `-L` returns zero bytes and looks exactly like "the deploy did not
> land". It did.

## Open — NOT done

- **The CLI is not on npm at 0.4.1.** `publish-cli.yml` gates the publish on the full
  `ci.yml`, which includes Playwright. All 25 visual baselines are `-darwin.png` and **no
  `-linux` baseline has ever been committed**, so on Linux CI every visual spec fails with
  "A snapshot doesn't exist … writing actual". The publish job is correctly `skipped`.
  This is pre-existing and explains why 0.4.0 was published by hand on Aug 8. The CLI suite
  itself is green in CI: **454 pass / 0 fail**. Three ways forward, none taken here because
  each is a judgement call: generate and commit Linux baselines; scope the visual specs to
  their platform; or publish manually. **Do not "fix" this by dropping Playwright from the
  publish gate** — the gate exists because this workflow once published with no tests at
  all.
- **Two `v0.4.0` tags exist and released nothing.** `cheaper-desktop`'s was moved to
  `v0.4.1`; `ownasquare/cheaper`'s `v0.4.0` remains, its publish job skipped.
- **Both Linux lanes emit `latest-linux.yml`** and `download-artifact` merges with
  `merge-multiple`, so one overwrites the other and electron-updater metadata is wrong for
  one Linux arch. Needs a per-arch update channel.
- **AppImage is published but not linked** from the website, for either architecture, and
  has no install-steps renderer. Pre-existing.
- **`cheaper-macos-x64.dmg` failed to upload three times** with wrangler `fetch failed`
  before succeeding on a retry. ~104 MB. Worth a retry loop in `put_r2` if it recurs.
